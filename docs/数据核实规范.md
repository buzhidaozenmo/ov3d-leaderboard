# 数据核实规范

本榜单的可信度取决于每一条数字都能回到论文。新增或修改 `data/papers.json` 前，按下面的顺序核对。

## 1. 先确认论文身份

- 标题、作者、年份、venue 是否与正式出版页一致（CVF / ACM / IEEE / 出版社页面，或 arXiv 的 comment/journal_ref）。
- 未正式发表：`venue_type: "preprint"`，页面会显示「预印本 · 未经同行评审」。不要凭 arXiv comment 猜一个会议。
- 同一工作的 arXiv 版本与正式版数字不一致时，以正式版为准，并在 `discrepancy` 字段记录差异。

## 2. 找到正确的 mIoU

- 只取论文中**明确标注 mIoU** 的表格或图；记录表号与页码，写进 `locator`。
- 确认类别集合与划分：
  - ScanNet v2：20 类，val；不要混入 ScanNet200、4 类 unseen、test。
  - nuScenes：LiDAR 16 类，val；确认是否使用 RGB / 多视角。
  - Matterport3D：21 类，test；注意 Matterport21/40/80/160 词表实验是不同设置。
- 同一方法有多个变体时（LSeg/OpenSeg、2D-3D ensemble、3D distill、stage1/stage2、不同教师），**每个变体单独一行**，不能取最好看的一个却不标注。

示例：OpenScene 的 ScanNet 数字有两条常见口径——
- 2D-3D Ensemble：54.2（LSeg）/ 47.5（OpenSeg）→ `family: "2d3d_ensemble"`
- 3D Distill：52.9（LSeg）/ 46.0（OpenSeg）→ `family: "3d_only"`

二者不能混排成同一行。

## 3. 一手来源与转引

- `source_kind: "primary"`：数值直接来自该论文自己的表格。
- `source_kind: "secondary"`：该论文没有报告这个数据集，数值来自他文对照表（例如 GeoGuide Table 1 汇总的 SAS / OV3D / PLA）。此时 `source` 必须写清引用论文与表号，页面会显示「转引」。
- 转引不是错，但必须让读者一眼看出不是原作者报告。

## 4. 开源状态

| 值 | 判定 |
| --- | --- |
| `yes` | 论文给出官方仓库，且仓库可访问、与该论文对应；必须填 `code_url` |
| `partial` | 只有部分代码/推理脚本，或权重需申请；仍填 `code_url` |
| `no` | 论文明确说明不公开，或作者确认无代码 |
| `unknown` | 找不到可信入口；**不要**因为“搜不到”就写 `no` |

GitHub 上同名仓库很多，必须用作者主页、论文脚注或 README 交叉确认。第三方复现不放 `code_url`。

## 5. 数值分歧

同一方法在不同论文里数值不同是常态（教师模型、训练预算、评测脚本不同）。处理方式：

1. 保留一手论文的值作为 `miou`。
2. 在 `discrepancy` 写一句「他文报告 X（来源）」。
3. 不静默替换、不取平均。

## 6. 多视角子榜的额外字段

加入 `multiview.html` 的方法除了主榜字段，还要在 `papers.json` 中写：

```jsonc
"tracks": ["ov", "multi_view"],
"mv": {
  "teacher_2d": "LSeg / OpenSeg / SEEM …",
  "correspondence": "点-像素投影 / 超点 / 掩码",
  "fusion": "均值 / 能力加权 / 不确定度 / 几何引导",
  "stage_3d": "3d_distill | self_distill | 2d3d_ensemble | few_label",
  "student_3d": "3D 学生或集成方式",
  "variant_note": "该行对应的变体"
}
```

只有确认论文真的做了多视角 2D→3D 对应与融合才加 `multi_view`；只做文本对齐或单视图蒸馏的不要加。子榜按论文最终配置排 mIoU，中间阶段（stage1、2D Fusion）不在子榜单列。

## 7. 核实字段

每条记录都要有：

- `verified: true`
- `verified_at: YYYY-MM-DD`
- 每个数据集结果的 `source`、`source_kind`、`locator`

没有核实的条目不进排名；抓取脚本写入的候选只停留在 `data/candidates.json`。

## 8. 复核周期

- 每季度重核一次 `verified_at`，尤其是标注为转引的条目。
- arXiv 新版本只更新元数据；除非论文修订了实验表，否则不改数值。
- 发现错误：改 `papers.json` → `python3 scripts/build.py --check` → 提交，页面与 Actions 会自动更新。

## 9. 常用核对入口

- CVF Open Access：`https://openaccess.thecvf.com/`
- arXiv HTML（表格可复制，优先于 PDF）：`https://arxiv.org/html/<id>`
- Semantic Scholar：查 venue、DOI、正式版链接
- 论文官方 GitHub：确认代码与论文的对应关系
